# B03 0.3.0 实现备注

依据：[PRD v0.4](../prd.md)。本文记录当前实现选择与数值边界，具体发布状态、测试数量、构建标记及浏览器证据见 [验收记录](./acceptance.md)，历史版本的结果不能替代本轮验证。

## 逻辑场地与信号

默认逻辑场地为 `1600 × 1000`，短边 `L = 1000`。玩家选点保留小数，不吸附网格；SVG 使用固定逻辑纵横比。尺寸变化只调整显示与触点映射，不重新开局或改写坐标。

第一关无屏障。第二关使用矩形 `{ x: 780, y: 230, width: 40, height: 540 }`，其左右边界为 `780 / 820`，上下边界为 `230 / 770`；两侧、两端均留有可选空间。地图装饰不参与计算。

信号在 `src/engine.js` 中统一计算：

```text
r = distance(source, point) / L
S = a × K / (r² + h²)
I = b + S
```

默认 `K = 100`、`h = 0.10`、`b = 5`。没有穿墙时 `a = 1`，穿墙时 `a = 0.5`；只对源贡献减半，背景不变。没有随机噪声，内部保留完整浮点读数，零距离也得到有限结果。

0.3.0 保留此模型。源贡献在 `r` 远大于 `h` 时近似平方反比；近距离由 `h²` 平滑，界面总读数还含背景，不能视为所有距离下都严格满足 `1/r²`。

屏障判断使用线段与矩形开放内部的裁剪区间。只有正长度内部相交才衰减，同一道墙仅衰减一次；切触角、沿边界或只碰到端点不衰减。数值实现使用 `geometryEpsilon = 1e-9` 个逻辑单位处理边界舍入：检查向内收缩该极小距离后的开放区域，并排除同量级的交段。这用于避免反算位置的几个浮点位差使切触突然变成穿墙，与玩家操作容差无关。

源、测点和最终定位点不能在墙内或墙边界上。源按连续随机值生成，默认与地图边缘保持 `0.02 × L` 的余量；下一局避开紧邻上一局源的位置。固定种子生成器支持复现，异常的恒定随机数输入也不会让生成过程无限循环。

## 固定仪表与显示

仪表接收总读数，先减去背景，再使用固定对数映射：

```text
Smax = K / h²
meter = log(1 + S / 20) / log(1 + Smax / 20)
```

结果限制在 `0—1`，所有正式记录、两关和演示使用同一尺度，不按当前最大读数重新拉伸。条长只代表信号强弱，不能解释为距离或成功率。

默认显示一位小数；界面在相近读数需要区分时增加显示精度，比较依据仍为完整读数。第二关提交前不告知具体测量是否穿墙，也不把读数增强直接解释成更靠近源。源和候选位置只在允许揭晓的状态呈现。

## 手机文字与固定距离参考

0.3.0 将手机主体说明与操作文字调整到约 `14—16 CSS px`，主要读数采用更大字号。地图文字和标记按照 SVG 实际显示尺度做逆缩放，标签保持约 `16 CSS px`；尺寸观察只重绘显示，场地、逻辑坐标、已选点和信号结果保持不变。标记仍锚定原逻辑位置，标签根据可见边界摆放，避免在地图边缘裁切。

地图上方新增固定的“无遮挡距离参考”。`readingReferences(config)` 仅使用配置与固定总读数 `[10, 100, 1000]`，不访问源、待测点或记录；因此选点、测量与同配置重玩均不会产生新的参考信息。其距离使用 `distanceForReading(value, config)` 反算：

```text
d = L × sqrt(K / (I - b) - h²)
```

该接口返回地图逻辑距离；非有限读数、不高于背景的读数或超过模型峰值的读数返回 `null`，峰值对应零距离。可选的衰减参数用于同模型反算，但界面参考尺始终采用无遮挡条件。超出地图的距离不截断，参考项同时保留 `distance`、占短边比例 `ratio` 和是否超过地图对角线的 `exceedsMap`。

默认参考值为：

| 总读数 | 距离 / 短边 | 显示方式 |
| --- | --- | --- |
| 1000 | 约 0.30 | 尺上刻度 |
| 100 | 约 1.02 | 尺上刻度 |
| 10 | 约 4.47 | 超过地图对角线，尺外标注“超出地图范围” |

尺与地图共用显示宽度，刻度横向位置为 `distance / config.width`，因此二者具有相同水平距离尺度。超过尺长但尚未超过地图对角线的自定义参考值注明“超出尺长”；模型不可达时注明当前参数下不可达。参考距离以短边倍数展示，不宣称实际物理单位，也不以测点为中心新增定位圈或在提交前显示候选。

参考尺旁显示“强度 ∝ 1/r²”，同时注明“远距离近似”和“r 为到源距离”。第二关补充“穿墙后源信号 ×0.5，背景不变”，系数来自配置；不告知某次未揭晓的测量是否穿墙。文案中的距离用于解释趋势，精确计算继续使用前述归一化距离与平滑模型。

## 状态与配置快照

`GameSession` 将等待选点、测量中、最终定位、结果和判定异常分开。开始测量时只扣一次机会；状态机拒绝测量中的重复确认和点位变动。完成测点保持不变，默认禁止与已有测点距离小于 `0.01 × L` 的新测量。

游戏状态和配置都以冻结快照提供。调整参数会更新下一局配置，本局继续使用开局时的配置；窗口尺寸变化不会替换本局状态。计时从开始挑战到首次确认定位，包含等待，不包含演示；判定异常与重试不额外增加已记录用时。

状态机通过单调时间戳推进测量，没有携带旧局数据的延迟回调。重玩、切关和返回开始页替换当前状态，旧测量不能在新局完成后写回。

首版配置校验限定每关 **3—5 次**。求解函数可接收 2—5 条记录作为内部计算接口，但玩家必须完成配置次数才能提交，不提供两次正式挑战或提前提交。支持更多次数需要同步评估屏障假设枚举、界面记录容量与验收覆盖。

0.2.0 默认 **4 次测量、1000 ms 等待**，完成后地图和记录区保留四个对应编号。三、四、五次与一秒、三秒等待仍可在开始页试玩设置中调整，修改只影响下一局。缩短读条不取消确认动作、位置锁定或防重复扣次规则。

演示使用独立固定源和正式模型，默认十二秒，可跳过、重看或返回；正式测量过程中没有演示入口。演示状态不消耗正式测量机会。

## 候选求解与公平判定

浏览器内部枚举第二关各记录的穿墙与未穿墙假设，三、四、五次分别最多 `8 / 16 / 32` 组。每组反推距离，以间距最大的两测点求圆交点，再用**全部记录**和实际屏障几何逐个验证，排除无效位置并合并数值重复解。第一关执行同样的距离与全部记录验证，无需枚举屏障假设。

内部几何先按地图短边归一化。对于远源和紧密共线测点，反算距离可能放大浮点舍入；实现传播与测点间距相关的舍入界，避免近切点被误认成无实数解，随后仍须通过完整读数验证。

数值参数与玩家空间容差分开：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `numericRelativeTolerance` | `1e-10` | 验证模型预测与完整读数，按 `max(1, 预测, 观测)` 缩放 |
| `geometryEpsilon` | `1e-9` 逻辑单位 | 屏障边界与极小交段的数值分辨率 |
| `candidateMergeDistance` | `0.001` 逻辑单位 | 合并舍入产生的重复候选，并检查真源在候选集合内 |
| `successRatio` | `0.05 × L`，默认 50 单位 | 玩家落点的成功或有效多解容差 |
| `nearRatio` | `0.10 × L`，默认 100 单位 | 接近有效候选的容差 |

等级按顺序判定：距真源不超过成功容差 → 定位成功；否则距另一候选不超过成功容差 → 合理判断；否则距最近候选不超过接近容差 → 接近可行位置；其余 → 尚未定位。边界包含在内，最终仍显示到真源的实际偏差。

### 量化定位偏差

揭晓后以 `distance(玩家落点, 真实源) / L × 100%` 显示“定位偏差”，越低越准。它是占地图短边的空间距离比例，不是成功概率；不使用 `100% − 偏差` 生成分数，超过 100% 时也不截断。界面舍入只影响显示，判定仍使用完整精度与原有容差。

存在有效多解时，另显示“距最近有效位置”：`min(distance(玩家落点, C 中各位置)) / L × 100%`。真实偏差与最近有效位置偏差同时保留并明确标注；镜像多解即使距真实源较远，仍可判为合理判断，不因新增指标受到降级。两项指标只在确认提交后显示，移动最终标记时不反馈。

没有候选，或候选集合未包含真源时，分类函数抛出程序异常。状态机保留测量记录并进入可重试的异常页，不给玩家失败等级。候选计算在提交时进行，提交前不展示候选、圆、圆弧或热图。

## 简洁界面

主视图突出地图、当前阶段、剩余次数、确认动作与必要读数，减少重复介绍和说明。详细帮助与试玩设置可折叠；开始页和结果页保留已知源演示，正式局不增加演示入口。历史记录、编号对应、选择与确认分离、错误恢复和结果含义仍需可用。

## 静态构建、版本与本地工具

`npm run dev` 直接服务源码，`npm run build` 生成 `dist/`，`npm run preview` 服务生成目录。服务器默认端口 `4173`，绑定 `127.0.0.1`，并提供 `/b03/` 本地项目子路径，设置 `Cache-Control: no-store`；这些行为用于开发，不等同于实际 Pages 网络与缓存行为。

构建将首页、样式和 `src/` 下的模块复制到静态目录，同时从这些内容计算统一的十二位哈希标记，替换入口及各层 JavaScript / CSS 引用的 `?v=` 参数。`release.json` 保留版本、哈希与文件列表；`.nojekyll` 随交付生成。`dist/` 被 Git 忽略，使用提交的源码和锁文件重新构建。

这能让拿到新首页的新会话请求新构建的资源；不能保证已经缓存的旧首页自行失效，也不会替换已开始单局的参数。发布后仍需在真实手机核对页面版本、刷新和旧二维码入口。当前显示版本在 `src/config.js`，包版本在 `package.json`，构建元数据版本在 `scripts/build.js`；修改版本时应同步更新，并检查源入口的版本参数。

`npm test` 使用 Node 内置测试工具。`npm run test:browser` 使用开发依赖 `@playwright/test`，由 `playwright.config.js` 选择本机 Chrome（`channel: 'chrome'`）；不向交付页面加入 Playwright，也不下载另一套浏览器。`npm ci --registry=https://registry.npmjs.org` 需要官方 npm 网络访问。

`?seed=...` 只用于开发复现：在相同配置和开局顺序下保持伪随机序列一致。玩家界面不显示种子或隐藏源坐标，但代码和运行状态都在浏览器内，可通过开发工具检查，不适合承担抗作弊、兑奖核验或统一排名。

## 待验证参数与交付边界

0.2.0 根据反馈将默认值改为四次测量、一秒等待，仍支持三至五次配置。0.3.0 根据手机试玩反馈放大文字并增加固定参考尺，默认测量节奏与信号模型保持不变。四次测量与短读条的实际体验、十二秒演示、场地比例与屏障位置、信号参数、仪表尺度、显示精度、5% / 10% 定位容差、2% 源边缘余量、1% 测点间距和 3% 共线提示阈值，均需结合后续试玩观察；偏差百分比和固定参考尺也需要验证玩家是否理解。

轻提示只检查玩家测点布局，最后一次测量前在布局近共线时提醒换方向；不读取隐藏源或推荐答案。是否容易理解、是否频繁误触、弱信号差异是否足够清楚，需结合真机和非专业玩家反馈判断。

本轮文字与参考尺改动的发布状态以发布记录为准，本文不代表新版已经上线。发布后需通过原网址与二维码核对 0.3.0 版本，并复测校园 Wi-Fi、移动网络、iOS / Android 微信与系统浏览器。重点检查手机横竖屏字号、边缘标签、参考尺和地图的尺度一致性，以及放大后是否影响邻近测点的辨认。

自动化的尺寸变化和浏览器交互验证不证明真实触屏、工具栏伸缩、微信内核或多人手机现场表现。还需邀请 10—15 名非专业参与者，记录理解、用时、误差、等级分布、误触和首次加载体验；未测试环境不能标记为通过。

必要资源加载后，当前页面的核心游戏操作不请求后端。首次访问需要网络；断网刷新、关闭后重开、PWA、离线缓存、账户、集中成绩和排行榜均不在首版交付范围。
