# B03「信号寻踪」

面向核能文化节的双关卡定位游戏。玩家在连续地图上选择测点，确认测量、比较读数，用完机会后提交信号源位置。第一关只考虑距离，第二关加入一道屏障；有效的镜像多解也可以得到认可。

当前应用版本为 **0.4.1**，发布分支为 `main`。本轮采用 **B「钛灰工程」**：亮暗主题、直角与少量切角、可读地图标记、本地数字字体，以及选新测点时的“上次读数”提示。玩法依据 [PRD v0.5](./prd.md)，美术与交互规范见 [design.md](./design.md)。默认三次测量、每次一秒，信号模型与公平判定保持不变。

[GitHub Pages 游戏入口](https://eivorchen.github.io/b03/) 保持原网址；本地测试使用 [http://127.0.0.1:4173/b03/](http://127.0.0.1:4173/b03/)。公开仓库为 [eivorchen/b03](https://github.com/eivorchen/b03)。0.4.1 已[成功发布](https://github.com/eivorchen/b03/actions/runs/39091868969)，详细验证见 [开发交接](./DEVELOPMENT_STATUS.md)。

主题首次跟随系统，手动选择后在本机保存；切换时保留测点、读数、测量计时和结果。应用使用原生 HTML、CSS、JavaScript，无账户、后端或运行时库，字体随静态资源提供。最新验证结果见 [开发交接](./DEVELOPMENT_STATUS.md) 与 [验收记录](./docs/acceptance.md)。

0.4.1 已通过完整 `npm run check`：**41 项 Node 测试、30 项浏览器测试**，构建标记 `26dc162b1a9e`；[验证日志](./docs/validation-0.4.1.log)。截图覆盖两主题、桌面和手机尺寸模拟，新版真机体验仍待试玩。

## 本地运行

需要 Node.js 22 或更高版本与 npm。本机已配置 Node.js 24.22.0 / npm 11.19.1，无需重复安装。以下命令均在 `b03` 目录执行：

```sh
npm run dev
```

浏览器打开 **http://127.0.0.1:4173/b03/**。开发服务器只监听 `127.0.0.1`，仅供本机使用；这个地址不能作为手机扫码或活动公开入口。编辑文件后刷新页面查看变更，按 `Ctrl+C` 停止服务器。

游戏运行和静态构建均不需要安装 npm 包。仅在运行浏览器自动化测试前安装锁定的开发依赖：

```sh
npm ci --registry=https://registry.npmjs.org
```

该步骤需要能够访问官方 npm 注册表。`@playwright/test` 只用于开发测试，使用本机已经安装的 Google Chrome；无需执行 `playwright install` 或下载额外浏览器。Playwright 配置使用 `channel: 'chrome'`，未安装本机 Chrome 的环境需要先具备对应浏览器。

## 测试与静态交付

```sh
# Node 内置测试：数学引擎、游戏状态与边界行为
npm test

# 使用本机 Chrome 的浏览器交互回归
npm run test:browser

# 构建并对 dist 静态交付运行同一套浏览器回归
npm run test:release

# 生成静态文件
npm run build

# 预览 dist 中的构建结果
npm run preview
```

开发与预览默认都使用端口 **4173**，启动另一个前先停止已运行的服务器。预览同样通过 **http://127.0.0.1:4173/b03/** 访问，仍只监听本机。必要时可用 `PORT=4174 npm run dev` 修改开发端口。

`npm run check` 按顺序执行 Node 测试、构建和静态交付的浏览器测试。`test:browser` 默认自动启动开发服务器；若 `4173` 已有服务器，会复用该服务。`test:release` 使用 `4174` 临时启动 `dist/` 预览，结束后关闭。浏览器自动化验证不能代替 iOS / Android 真机、微信内置浏览器、校园网和移动网络验收；命令是否通过及其实际环境，以验收记录为准。

构建生成 `dist/`，包含首页、样式、模块、本地字体及许可、`.nojekyll` 与 `release.json`。**`dist/` 是可静态发布的交付目录**，通过源码和锁文件可重新生成，不提交到 Git。资源采用相对路径，本地 `/b03/` 路径用于检查与 Pages 项目子路径相同的加载方式。

构建为首页引用和各级模块引用附加同一个内容哈希版本标记，减少更新后混用不同构建资源的风险；页面显示游戏版本号，`dist/release.json` 记录构建标记。拿到新首页才会使用新标记，旧首页缓存仍需在发布验收时检查。

## GitHub Pages 发布

稳定入口为 **https://eivorchen.github.io/b03/**，发布来源为 GitHub Actions。工作流 [.github/workflows/pages.yml](./.github/workflows/pages.yml) 在 `main` 收到推送时运行，也可在 GitHub 的 Actions 页面手动触发。它使用 Node.js 24，依次安装锁定依赖、执行 `npm test`、运行 `npm run build`，再上传并发布 `dist/`；测试或构建失败时不会进入部署。

首次部署已[成功完成](https://github.com/eivorchen/b03/actions/runs/38858692029)。用户另行安排发布后，应先在本机运行 `npm run check`，提交并推送 `main`，然后检查 [Actions 发布结果](https://github.com/eivorchen/b03/actions/workflows/pages.yml) 和线上页面。云端工作流运行 Node 测试，本机 Chrome 的完整浏览器回归仍需在发布前执行。无需将 `dist/` 提交到仓库。

## 游玩与调试

- 开始页可直接选择任一关，观看独立的已知源演示，或直接开始。
- 点击地图仅放置待选标记；点击“确认测量”才消耗机会，测量过程中锁定位置。
- 用完配置次数后进入最终定位，单独确认后才揭晓源、等级和实际偏差。
- 定位偏差为距真实源 / 地图短边 × 100%，越低越准；存在有效多解时另显示距最近有效位置的同尺度百分比，公平分类保持不变。这不是成功概率或百分制得分。
- 可取消尚未确认的选点、重新开始、切换关卡、返回开始页；结果页可重看演示。
- 默认每关三次、每次等待一秒，完成后保留三个编号测点及对应记录。开始页的试玩设置仍支持三、四、五次，以及一秒或三秒等待；调整只作用于下一局。
- 主视图突出地图、必要状态和确认动作；详细帮助与试玩设置可折叠，开始页和结果页保留演示入口。
- 手机主体文字约 14—16 CSS 像素，地图标签通过逆缩放保持约 16 CSS 像素；地图仍按原逻辑坐标等比显示。
- 地图上方参考尺与地图保持相同水平尺度。无遮挡总读数 1000 / 100 约对应 0.30 / 1.02 倍短边；10 对应约 4.47 倍短边，单独注明超出地图范围。参考尺仅依赖配置，不透露本局源或测量路径。
- 公式“强度 ∝ 1/r²”注明“远距离近似”。精确模型使用归一化距离 `r = 到源距离 / 地图短边`，计算 `I = b + aK / (r² + h²)`，近距离有限；第二关穿墙仅让源贡献乘以 0.5，背景不变。
- 所有必要资源加载后，当前页面中的演示、测量、判定、切关与重玩均在本地执行。首版不承诺断网首次访问、刷新或重新打开，不提供 PWA 或离线缓存。

可通过固定种子复现开发场景：

```text
http://127.0.0.1:4173/b03/?seed=b03-debug
```

同一种子、配置和开局操作顺序会得到同一组源位置。种子及隐藏源坐标不显示在玩家界面，演示也不使用正式局的源。**所有前端代码与浏览器内存都可被检查，这不是抗作弊或成绩核验方案。** 正式二维码应使用不带调试参数的已验证 HTTPS 游戏地址。

## 项目结构

| 路径 | 用途 |
| --- | --- |
| `index.html` | 入口、资源加载与失败重试 |
| `styles.css` | 钛灰工程亮暗主题、桌面与手机布局 |
| `design.md` | 美术、字体、几何形状及交互指导 |
| `src/theme.js` | 系统主题、本地选择与界面同步 |
| `assets/fonts/` | 本地数字字体及许可证 |
| `src/app.js` | 页面文案、地图交互、演示、读数与复盘呈现 |
| `src/config.js` | 集中参数与校验、不可变单局配置 |
| `src/engine.js` | 信号、屏障、源生成、候选求解与等级判定 |
| `src/session.js` | 与界面分离的游戏状态机、测量计时和异常恢复 |
| `scripts/serve.js` | 仅供本机的静态开发与预览服务器 |
| `scripts/build.js` | 静态构建及统一资源版本标记 |
| `.github/workflows/pages.yml` | `main` 自动测试、构建及 GitHub Pages 发布 |
| `scripts/capture.js` | 对本机 4173 预览生成隔离 Chrome 验收截图 |
| `tests/`、`playwright.config.js` | 自动化回归与本机 Chrome 配置 |
| `docs/implementation-notes.md` | 模型、数值边界、实现选择与待验证参数 |
| `docs/acceptance.md` | 实际执行的验证证据与剩余缺口 |
